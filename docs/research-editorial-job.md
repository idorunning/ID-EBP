# Research editorial job — original summaries and evidenced gap filling

Added 20 November 2026. Migration `20261120100000_research_stage_gates_and_editorial_job.sql` (generated by
`scripts/build-research-editorial-migration.mjs`; edit the template or `scripts/research-stage-assessment.sql`, then
regenerate — `npm test` fails if the two drift apart).

## What it does

- Writes **original** one- to two-sentence signposting summaries in British English. Abstracts and publisher
  text are read for understanding only; drafts that share 10 or more consecutive words with the evidence are rejected.
- Fills `authors`, `year` and `tags` **only where missing** (or a placeholder such as "none listed"), from the
  evidence page or DOI registry metadata. Titles and URLs are never changed. A non-empty summary is replaced only
  with a stated reason (`copied_abstract`, `page_capture`, `not_descriptive`, `inaccurate`).
- Records an evidence URL for **every** field (`private.research_field_evidence`, append-only), then records the
  Stage 4 review through the same gate logic as `scripts/advance-research-stages.mjs` (`private.research_stage_apply`).
- Signs off Stage 5 only with a live-search exact match and a link check from the last seven days
  (`private.research_editorial_signoff`).
- Anything that cannot be evidenced is **held** with a specific reason. Records whose evidence page is unreachable
  return to the queue after three days (at most three attempts). Nothing is guessed and no record is promoted to
  clear a queue.

Reviewer label: `Claude (automated evidence review)`.

## Database objects

| Object | Purpose |
|---|---|
| `private.research_stage_rows(reviews, reviewed_only)` | Stage gates (identical SQL to the runner) |
| `private.research_stage_apply(reviews)` | Runner `--apply` in the database |
| `private.research_stage_state` / `_transitions` / `_snapshots` | Stage history; hourly `id-ebp-research-stage-refresh` at :40 |
| `private.research_stage_report()` | Stage panel data for Admin → Database → Live Enrichment |
| `private.research_editorial_queue` / `_runs` | Resumable, leased work queue and run checkpoints |
| `private.research_editorial_seed/claim/submit/signoff/finish` | Job steps (service role only) |

Idempotency: claims are leased for 45 minutes and stamped with the record fingerprint; a submission for a record
that changed after its claim is re-queued, a spent lease is skipped, and repeating a sign-off creates no duplicate
checkpoint. Each submission is at most 50 records, within the safety catch's 500-update limit.

## One batch (what the scheduled task does)

```sql
select private.research_editorial_seed();                                   -- tops up the queue (idempotent)
select private.research_editorial_claim(25, 'Claude (automated evidence review)');  -- returns {run, ids}
```

```sh
node scripts/editorial-batch.mjs evidence --dir /tmp/ed ID...    # digest of each record and its evidence
# write /tmp/ed/drafts.json: [{id, summary?, replace_reason?, authors?, year?, tags?, evidence_default?, evidence?, hold?}]
node scripts/editorial-batch.mjs check --dir /tmp/ed --run RUN /tmp/ed/drafts.json   # prints the submit call
```

Run the printed `select private.research_editorial_submit(...)`. Then sign off records at Stage 4:

```sql
select coalesce(jsonb_agg(id),'[]') from (select id from private.research_stage_rows() where stage=4 limit 60) x;
```

```sh
node scripts/editorial-batch.mjs live --run RUN ID...            # prints the sign-off call
```

Finish with `select private.research_editorial_finish('RUN','note');` (releases unfinished claims, refreshes stages).

## Monitoring

```sql
select status, count(*) from private.research_editorial_queue group by 1;
select * from private.research_editorial_runs order by started_at desc limit 10;
select held_reason, count(*) from private.research_editorial_queue where status='held' group by 1 order by 2 desc;
select private.research_stage_report();
```

Pause: disable the scheduled task. Queue rows, run logs and evidence are retained; nothing needs resetting.
